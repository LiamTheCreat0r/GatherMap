## 1. Quick start

```bash
flutter pub get
flutter analyze                 # must stay clean (CI gate)
flutter test                    # no Supabase config required
flutter run --dart-define-from-file=.env
```

Supabase configuration is **compile-time**: it must be supplied at build/run
time via `--dart-define-from-file=.env`. See
[section 5](#5-environment-variables-env).

CI (`.github/workflows/dart.yml`, `main` branch):

```text
flutter pub get → flutter analyze → flutter test
```

The `dart format` check exists in the workflow but is **commented out**:
formatting is not enforced today.

## 2. Code architecture

### 2.1 Overview

The project is **feature-first**, with a shared core and a
`data → domain ← presentation` split inside each feature.

```text
lib/
├── main.dart                     # bootstrap: Logs.init → Supabase.initialize → runApp
├── app/
│   ├── app.dart                  # MyApp: providers, theme, routes
│   └── shell/
│       ├── nav_bar_shell.dart    # IndexedStack + bottom bar
│       └── navbar.dart           # navigation bar (SVG icons)
├── core/                         # cross-feature, imports no feature
│   ├── config/environment.dart   # compile-time constants
│   ├── di/providers.dart         # ONLY place where implementations are chosen
│   ├── error/describe_error.dart # human-readable error message
│   ├── logging/logs.dart         # application logger
│   ├── routing/app_routes.dart   # named routes + current route
│   ├── state/base_controller.dart# base class of every controller
│   ├── theme/                    # app_themes, custom_colors, custom_text_styles
│   └── widgets/                  # PageHeader, SectionTitle, Avatar, LoadingDots
├── data/
│   └── supabase/supabase_service.dart  # lazy access to the client
├── models/                       # generated by Supadart — DO NOT EDIT
└── features/
    ├── events/
    │   ├── data/                 # data source, mapper, repository impl, AddressService
    │   ├── domain/               # entity, contracts, pure rules
    │   └── presentation/         # controller, pages, widgets
    ├── map/presentation/         # map page, widgets (MapLibre, pins)
    ├── chats/presentation/
    ├── circles/presentation/
    ├── friends/presentation/
    ├── invitations/presentation/
    └── profile/presentation/
```

### 2.2 Dependency rule

```text
presentation ──→ domain ←── data
```

| Layer           | May import                                  | Must not import              |
| --------------- | ------------------------------------------- | ---------------------------- |
| `domain/`       | other `domain/` files                       | Flutter, Supabase, `models/` |
| `data/`         | `domain/`, `core/`, `data/`, `models/`      | `presentation/`              |
| `presentation/` | `domain/`, `core/`, Flutter                 | Supabase, `data/`, `models/` |

These rules are enforced automatically by `test/architecture_test.dart` (a
textual scan of `import` lines). A violation fails `flutter test`.

In practice:

- a controller only knows an **interface** declared in `domain/`;
- the Supabase implementation is chosen **once**, in `core/di/providers.dart`;
- generated row classes (`lib/models/*.dart`) stop at the **mapper** in
  `data/`.

### 2.3 How a feature flows (example: creating an event)

```text
CreateEventDialog (presentation)
        │  context.read<EventController>().create(...)
        ▼
EventController (presentation)      extends BaseController
        │  _repository.create(NewEvent(...))
        ▼
EventRepository (domain, interface)
        │
        ▼
SupabaseEventRepository (data)
        │  _mapper.toInsert(draft) → EventRemoteDataSource
        ▼
EventRemoteDataSource (data)
        │  client.event.insert(payload).select()
        ▼
Supabase / `event` table
```

### 2.4 Dependency injection

`lib/core/di/providers.dart` is the single wiring point:

```dart
class AppDependencies {
  AppDependencies({SupabaseService? service})
    : _service = service ?? SupabaseService() {
    eventRepository = SupabaseEventRepository(
      EventRemoteDataSource(_service),
      const EventMapper(),
    );
  }

  late final EventRepository eventRepository;
  late final AddressSearch addressSearch = AddressService();
}
```

`buildProviderScope(child: ...)` wraps the app in the `MultiProvider`. The
`ChangeNotifierProvider`s are **lazy**: a controller is only built on the first
`context.read`/`context.watch`.

> **Rule of thumb**: building the graph performs no I/O. `SupabaseService`
> resolves `Supabase.instance.client` on first access. That is what lets the
> app (and the tests) mount without calling `Supabase.initialize`
> (`test/app/providers_test.dart`).

Inside a widget:

```dart
// Read without listening (actions, callbacks)
final controller = context.read<EventController>();

// Listen to a single slice of state
final events = context.select<EventController, List<Event>>((c) => c.events);

// Listen to the whole controller
final controller = context.watch<EventController>();
```

### 2.5 State: `BaseController`

Every controller extends `BaseController`
(`lib/core/state/base_controller.dart`), a `ChangeNotifier` exposing:

| Member       | Purpose                                            |
| ------------ | -------------------------------------------------- |
| `status`     | `idle` → `loading` → `ready` / `error`             |
| `isLoading`  | shorthand for `status == loading`                  |
| `hasError`   | shorthand for `status == error`                    |
| `error`      | human-readable message (through `describeError`)   |
| `isWatching` | a realtime subscription is active                  |

Three protected helpers:

```dart
// Write with no return value
Future<void> create(...) => runAction(() async {
  await _repository.create(...);
});

// Read with a return value (null on failure)
Future<Event?> fetchById(String id) => runQuery<Event?>(() async {
  return _repository.fetchById(id);
});

// Realtime
void watch() => watchTable(
  _repository.watch(),
  onData: (rows) => _events = rows,
);
```

**They never throw**: failures land in `status`/`error`. The UI renders
`controller.error` instead of handling a `try/catch`.

`notifySafely()` announces a change made directly to a field (it does nothing
after `dispose`). `stopWatch()` cancels the realtime subscription; `dispose()`
calls it automatically.

### 2.6 Errors

`describeError(Object error)` (`lib/core/error/describe_error.dart`) turns a
Supabase failure into a displayable message:

```text
PostgrestApiException(message: 'permission denied', errorCode: '42501')
    → "permission denied (42501)"

PostgrestApiException(message: 'not found', statusCode: 404)
    → "not found (HTTP 404)"

RealtimeSubscribeException(RealtimeSubscribeStatus.timedOut)
    → "Realtime subscription failed: timedOut"

StateError('boom')
    → "Bad state: boom"
```

### 2.7 Theme

Two `ThemeExtension`s carry the design system:

- `CustomColors` — `mainBackgroundColor`, `cardColor`, `accentColor`,
  `borderColor`, `primaryTextColor`, `dangerColor`, etc.
- `CustomTextStyles` — `pageTitleStyle`, `mainTitleStyle`, `subTitleStyle`,
  `bodyTextStyle`, `actionStyle`, `labelStyle`, `legendStyle`.

Access:

```dart
final colors = context.colors;         // BuildContext extension
final textStyles = context.textStyles;

// Or, if you prefer being explicit:
final colors = Theme.of(context).extension<CustomColors>()!;
```

Light/dark mode follows `AppThemes.themeModeValue` (`ThemeMode.system` by
default) and can be forced with `AppThemes.setThemeMode(...)`. The active theme
is resolved by `MaterialApp`: **do not branch on `Brightness` by hand**, reading
the extensions is enough.

### 2.8 Routing and shell

- `AppRoutes` centralises named routes (`/events`, `/map`, … and `/events/:id`).
- `CurrentRoute.name` (a `ValueNotifier`) tracks the top route via
  `currentRouteObserver`, registered on `MaterialApp`.
- `NavBarShell` hides the bottom bar when the current route matches
  `AppRoutes.hiddenNavRoutes`. To add a detail screen: declare the route and add
  it to `hiddenNavRoutes`.
- The four tabs live in an `IndexedStack`, and each tab is only built the first
  time it is visited: starting MapLibre at launch causes an ANR.

### 2.9 Generated code

`lib/models/*.dart` is produced by **Supadart** from the Supabase schema
(`supadart.yaml`, output `lib/models/`). **Never edit these files by hand.**

```bash
# SUPABASE_URL and SUPABASE_API_KEY (secret key) must be set
supadart
# or explicitly
supadart --url <url> --key <secret>
```

Each table exposes a `SupabaseClient` extension (`client.event`, `client.user`,
…) and a row class with its columns (`Event.c_scheduledAt`, `Event.insert(...)`,
`Event.update(...)`).

The `supabase/` directory (CLI config + migrations) is gitignored.

## 3. The logger

The logger wraps `package:logging` in `lib/core/logging/logs.dart`.

### 3.1 Initialisation

Called **once**, at startup, before any log — `main.dart` already does it:

```dart
import 'package:gathermap/core/logging/logs.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  Logs.init();                       // idempotent
  await Supabase.initialize(/* ... */);
  runApp(const MyApp());
}
```

`init()` sets the root level:

- **debug**: `Level.ALL`;
- **release**: `Level.WARNING` — so `debug`/`info` are dropped in production.

Every record is written with `debugPrint` in this format:

```text
2026-10-19T10:24:31.123 [INFO] EventController: 12 events loaded
  error: ...
<stack trace>
```

### 3.2 Usage

There is two way of using it: 

**Class-named logger** (recommended: the name shows up in the output):

```dart
import 'package:gathermap/core/logging/logs.dart';
import 'package:logging/logging.dart';

class EventController extends BaseController {
  static final Logger _log = Logs.forClass('EventController');

  Future<void> fetch() async {
    _log.fine('fetch: starting');            // debug
    _log.info('fetch: ${_events.length} events');
    try {
      // ...
    } catch (error, stackTrace) {
      _log.warning('fetch: failed', error, stackTrace);
      rethrow;
    }
  }
}
```

**Static shortcuts** (shared `App` logger):

```dart
Logs.debug('debug message');               // FINE level
Logs.info('information');
Logs.warning('warning', error, stackTrace);
Logs.error('error', error, stackTrace);    // SEVERE level
```

| Call                                        | `logging` level | Visible in release |
| ------------------------------------------- | --------------- | ------------------ |
| `Logs.debug(...)` / `_log.fine(...)`        | `FINE`          | no                 |
| `Logs.info(...)` / `_log.info(...)`         | `INFO`          | no                 |
| `Logs.warning(...)` / `_log.warning(...)`   | `WARNING`       | yes                |
| `Logs.error(...)` / `_log.severe(...)`      | `SEVERE`        | yes                |

### 3.3 Good practices

- Never log personal data (email, password, exact location) or the Supabase key.
- A controller should not log an error **and** let it bubble as an exception:
  here controllers do not throw, they fill in `error`. Log where the error is
  actually handled.
- Avoid `print`: it cannot be filtered by level and stays in production code.

### 4.3 Per-package details

#### `provider` — state and injection

Wiring is centralised in `core/di/providers.dart`:

```dart
Widget buildProviderScope({required Widget child, AppDependencies? dependencies}) {
  final deps = dependencies ?? AppDependencies();
  return MultiProvider(
    providers: [
      Provider<AddressSearch>.value(value: deps.addressSearch),
      ChangeNotifierProvider(create: (_) => EventController(deps.eventRepository)),
      // ...
    ],
    child: child,
  );
}
```

Rules:

- `context.read<T>()` in a callback or method (`initState`, `onPressed`): does
  not listen.
- `context.watch<T>()` in `build`: rebuilds on every `notifyListeners()`.
- `context.select<T, R>((t) => ...)` to react to one field only.
- To test an isolated widget, go through `buildProviderScope(child: ...)` or
  provide a `ChangeNotifierProvider.value` with a controller driven by a fake
  repository.

#### `supabase_flutter` + `postgrest` — data

Access **always** goes through `SupabaseService`, never through
`Supabase.instance` inside a feature:

```dart
class SupabaseService {
  SupabaseService({SupabaseClient? client}) : _client = client;
  final SupabaseClient? _client;

  SupabaseClient get client => _client ?? Supabase.instance.client;
}
```

The client is resolved lazily: building the graph never touches the network.
Queries use the generated extensions:

```dart
final rows = await client.event
    .select()
    .gte(row.Event.c_scheduledAt, nowUtc)
    .order(row.Event.c_scheduledAt);
final events = row.Event.converter(rows);
```

Realtime:

```dart
client.event
    .stream(primaryKey: [row.Event.c_id])
    .order(row.Event.c_scheduledAt, ascending: false);
```

#### `maplibre_gl` — map

Used by `features/map/presentation/widgets/map_widget.dart`.

Key points:

- The map is a **platform view**: it does not work in widget tests without a
  stub (see [section 6](#6-writing-tests)).
- The style loads asynchronously. Sources and layers can only be added from
  `onStyleLoadedCallback`, **never** from `onMapCreated` (otherwise
  `STYLE_NOT_READY`).
- Markers are native symbols: the pin is rendered to PNG
  (`renderEventPinPng`) and registered with `addImage`, and a GeoJSON `Feature`
  references it. MapLibre then keeps the pin glued to its coordinate while the
  map moves.
- `LoadingDots` covers the map until the style is ready.

#### `flutter_svg` — icons

The four tabs use 24×24 SVGs from `assets/icons/`, declared in `pubspec.yaml`:

```yaml
flutter:
  assets:
    - assets/icons/
```

The active/inactive state comes from `ColorFilter.mode(color, BlendMode.srcIn)`:

```dart
SvgPicture.asset(
  'assets/icons/map.svg',
  width: 24,
  height: 24,
  colorFilter: ColorFilter.mode(activeColor, BlendMode.srcIn),
)
```

#### `google_fonts` — typography

`CustomTextStyles.main` declares styles with `GoogleFonts.nunito(...)` and
`GoogleFonts.outfit(...)`. The package resolves the fonts; do not build a
`TextStyle` with a hand-written font family inside a page — go through
`context.textStyles`.

#### `http` — geocoding

`AddressService` calls the MapTiler Geocoding API:

```dart
class AddressService implements AddressSearch {
  AddressService({http.Client? client, String? apiKey})
    : _client = client ?? http.Client(),
      _apiKey = apiKey ?? defaultApiKey;

  Future<List<AddressSuggestion>> search(String query, {int limit = 6}) async { ... }
}
```

Both `client` and `apiKey` are injectable: tests pass a `MockClient` and never
hit the network. The MapTiler key is currently hard-coded
(`AddressService.defaultApiKey`) and shared with the map style — it should move
to an environment variable.

#### `logging` — logging

See [section 3](#3-the-logger).

#### `intl` and `cupertino_icons`

Present in `pubspec.yaml` but **unused** in the current code:

- `intl`: dates are formatted manually (`_monthsFr` in `events_list.dart`);
- `cupertino_icons`: the app only uses Material icons.

They can be removed without impact, or adopted to standardise date formatting.

## 5. Environment variables (`.env`)

### 5.1 Principle

Flutter **does not read** a `.env` file by itself. The file is injected at
compile time by `--dart-define-from-file`:

```bash
flutter run   --dart-define-from-file=.env
flutter build apk --dart-define-from-file=.env
```

Code then reads the values with `String.fromEnvironment`:

```dart
const supabaseUrl = String.fromEnvironment('SUPABASE_URL');
```

A `String.fromEnvironment` value **must be `const`**: it is baked into the
binary at compile time. Rebuild after any change to `.env`.

### 5.2 Existing variables

| Variable                   | Read by                        | Purpose                                        |
| -------------------------- | ------------------------------ | ---------------------------------------------- |
| `SUPABASE_URL`             | `lib/main.dart`                | Supabase project URL                           |
| `SUPABASE_PUBLISHABLE_KEY` | `lib/main.dart`                | Public (client) key                            |
| `SUPABASE_DB_PASSWORD`     | Supabase CLI                   | Database password, outside the app             |
| `SUPABASE_API_KEY`         | Supadart CLI (not in `.env`)   | **Secret** key used for type generation        |

`lib/core/config/environment.dart` declares two additional constants that are
currently unused:

```dart
abstract final class Environment {
  static const restApiKey = String.fromEnvironment('SUPABASE_REST_API_KEY');
  static const restApiUrl = String.fromEnvironment('SUPABASE_REST_API_URL');
}
```

### 5.3 Adding a variable

1. **Add the line to `.env`** (gitignored file):

   ```dotenv
   SUPABASE_URL=https://xxxxxxxx.supabase.co
   SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
   MAPTILER_API_KEY=xxxxxxxx
   ```

2. **Declare it in `lib/core/config/environment.dart`** (with a default value
   when it is optional):

   ```dart
   abstract final class Environment {
     static const restApiKey = String.fromEnvironment('SUPABASE_REST_API_KEY');
     static const restApiUrl = String.fromEnvironment('SUPABASE_REST_API_URL');

     static const mapTilerApiKey = String.fromEnvironment(
       'MAPTILER_API_KEY',
       defaultValue: '',
     );
   }
   ```

3. **Use it**:

   ```dart
   final apiKey = Environment.mapTilerApiKey;
   ```

4. **Pass it at build/run time**:

   ```bash
   flutter run --dart-define-from-file=.env
   ```

   A one-off value can also be passed directly:

   ```bash
   flutter run --dart-define=MAPTILER_API_KEY=abc123
   ```

### 5.4 Good practices

- `.env` is **gitignored**: never commit it, and never put a generation secret
  in it (`SUPABASE_API_KEY` / `service_role`).
- Any `--dart-define` value is **embedded in clear text** in the binary: it is
  not suitable for a secret. Only the *publishable* key belongs on the client.
- Provide a `defaultValue` for optional variables, and fail explicitly at
  startup when a critical one is missing.
- Tests need no variable at all: they touch neither Supabase nor the network.
- A missing `.env` produces empty values, not a compile error — it is
  `Supabase.initialize` that fails afterwards.

## 6. Writing tests

### 6.1 Commands

```bash
flutter test                                              # whole suite
flutter test test/features/events/presentation/event_controller_test.dart
flutter test --plain-name "an event exactly at [now] counts as past"
```

Tests need **no `.env`, no Supabase instance and no network**.

### 6.2 Layout

The `test/` tree mirrors `lib/`:

```text
test/
├── architecture_test.dart                 # layering guardrails
├── widget_test.dart                       # navigation shell
├── app/providers_test.dart
├── core/
│   ├── error/describe_error_test.dart
│   └── state/base_controller_test.dart
├── features/
│   ├── events/
│   │   ├── data/{address_service,event_mapper}_test.dart
│   │   ├── domain/event_schedule_test.dart
│   │   └── presentation/event_controller_test.dart
│   ├── map/presentation/event_pin_test.dart
│   ├── chats/presentation/message_controller_test.dart
│   └── profile/presentation/user_controller_test.dart
└── models/*_test.dart                    # generated-code payloads
```

Naming: `<tested_file>_test.dart`.

### 6.3 Pure unit test

For a business rule with no I/O, inject the clock instead of reading
`DateTime.now()`:

```dart
test('an event exactly at [now] counts as past', () {
  final now = DateTime(2026, 10, 15, 12);

  final result = splitUpcoming([_event('now', now)], now: now);

  expect(result.upcoming, isEmpty);
  expect(result.past, hasLength(1));
});
```

### 6.4 Controller + fake repository

No mockito/mocktail: write a **hand-written fake** implementing the domain
interface.

```dart
class _FakeEventRepository implements EventRepository {
  _FakeEventRepository({this.events = const [], this.failure});

  List<Event> events;
  final Object? failure;
  EventScope? lastScope;
  String? deletedId;

  Future<T> _guard<T>(T Function() body) async {
    if (failure != null) throw failure!;
    return body();
  }

  @override
  Future<List<Event>> fetch({EventScope scope = EventScope.all}) {
    lastScope = scope;
    return _guard(() => events);
  }

  @override
  Future<void> delete(String id) => _guard(() => deletedId = id);

  // ... remaining members: neutral return
}

test('a failing fetch records the error instead of throwing', () async {
  final controller = EventController(
    _FakeEventRepository(failure: StateError('offline')),
  );
  addTearDown(controller.dispose);

  await controller.fetch();

  expect(controller.status, ControllerStatus.error);
  expect(controller.error, contains('offline'));
});
```

Key points:

- always `addTearDown(controller.dispose)` (or `tearDown`);
- assert **effects** (controller state, recorded calls) rather than
  implementation;
- cover both paths: success and failure;
- controllers do not throw, so assert `status`/`error`, not `throwsA`.

### 6.5 HTTP without the network

`package:http/testing.dart` provides `MockClient`:

```dart
final service = AddressService(
  client: MockClient((_) async => http.Response(
    '{"features": [{"place_name": "Café de la Gare", "center": [2.35, 48.85]}]}',
    200,
  )),
);

final results = await service.search('café');
expect(results.single.placeName, 'Café de la Gare');
```

For a call that must **not** happen:

```dart
var calls = 0;
final service = AddressService(client: MockClient((_) async {
  calls++;
  return http.Response('{}', 200);
}));

await service.search('   ');
expect(calls, 0);
```

### 6.7 Project-specific pitfalls

**MapLibre**: mounting the app creates the platform view and its `dispose()`
throws `LateInitializationError`. Replace the plugin factory:

```dart
class _FakeMapLibrePlatform extends MapLibreMethodChannel {
  @override
  Widget buildView(
    Map<String, dynamic> creationParams,
    OnPlatformViewCreatedCallback onPlatformViewCreated,
    Set<Factory<OneSequenceGestureRecognizer>>? gestureRecognizers,
  ) => const SizedBox.shrink();

  @override
  // ignore: must_call_super
  void dispose() {}
}

final originalCreateInstance = MapLibrePlatform.createInstance;

setUp(() {
  MapLibrePlatform.createInstance = () => _FakeMapLibrePlatform();
});

tearDown(() {
  MapLibrePlatform.createInstance = originalCreateInstance;
});
```

**`pumpAndSettle` never quiesces** while the Map tab is mounted: `LoadingDots`
animates forever under the fake platform. Use bounded `pump`s:

```dart
await tester.tap(find.byType(SvgPicture).at(1));
await tester.pump();
await tester.pump(const Duration(milliseconds: 300));
```

**Generated code**: tests in `test/models/` check payloads (`Event.insert`,
`Event.update`) and `fromJson` tolerance. They act as a safety net across a
Supadart regeneration.

**Architecture guardrails**: `test/architecture_test.dart` reads files under
`lib/` with `dart:io`. It must run from the repository root (which `flutter
test` does). It fails when:

- a `domain/` file imports Flutter, Supabase, `models/`, `data/` or
  `presentation/`;
- a migrated feature imports Supabase/`data/`/`models/` from `presentation/`;
- a `data/` file imports `presentation/`.

### 6.8 Pre-push checklist

```bash
flutter analyze     # no issues
flutter test        # all green
```

## 7. GitHub conventions

Source: `STYLE_GUIDE.md`.

### 7.1 Branches

| Goal                | Pattern             | Example               |
| ------------------- | ------------------- | --------------------- |
| Add a feature       | `feat-(description)`| `feat-map-clustering` |
| Fix / adjust        | `fix-(description)` | `fix-navbar-padding`  |

One branch = one topic. Start from `main`, open a pull request back into `main`,
and CI (`flutter analyze` + `flutter test`) must pass before merging.

### 7.2 Commits

| Goal                        | Format               | Example                     |
| --------------------------- | -------------------- | --------------------------- |
| Create a feature            | `Feat-(Description)` | `Feat-(Map-clustering)`     |
| Update / fix                | `Fix-(Description)`  | `Fix-(Navbar-bottom-inset)` |
| Documentation               | `Doc-(Description)`  | `Doc-(Architecture-update)` |

Practical rules:

- one commit = one coherent change that compiles;
- short description, English or French, but **consistent** within a PR;
- do not mix a refactor, mass formatting and a feature in the same commit;
- GitHub-generated merge commits (`Merge pull request #…`) are normal on
  `main`.

### 7.3 Code naming

| Element            | Convention   | Example                         |
| ------------------ | ------------ | ------------------------------- |
| Folders/files      | `snake_case` | `event_repository_impl.dart`    |
| Classes/enums      | `PascalCase` | `EventController`, `EventScope` |
| Methods/members    | `camelCase`  | `fetchUpcoming`, `isPinnable`   |

Lints: `flutter_lints` via `analysis_options.yaml`. `build/`, `android/`,
`ios/`, `web/`, `windows/`, `macos/` and `linux/` are excluded from analysis.

### 7.4 Where to put a new file

| You are adding…                     | Location                                              |
| ----------------------------------- | ----------------------------------------------------- |
| An entity or a business rule        | `lib/features/<feature>/domain/`                      |
| A repository contract               | `lib/features/<feature>/domain/<x>_repository.dart`   |
| Supabase / API access               | `lib/features/<feature>/data/`                        |
| A controller or a page              | `lib/features/<feature>/presentation/`                |
| A shared widget                     | `lib/core/widgets/`                                   |
| A feature-specific widget           | `lib/features/<feature>/presentation/widgets/`        |
| A colour / text style               | `lib/core/theme/` (existing extension)                |
| A route                             | `lib/core/routing/app_routes.dart`                    |
| A dependency wiring                 | `lib/core/di/providers.dart`                          |

After adding a feature, make sure `test/architecture_test.dart` passes and that
the feature is **not** added to `unmigratedFeatures` (that list may only
shrink).
