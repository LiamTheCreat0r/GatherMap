# Gather Map

## Supabase Configuration

Pull your project down

```bash
npm i -g supabase          # or: brew install supabase/tap/supabase
supabase login
supabase init              # creates supabase/ folder with config.toml
supabase link --project-ref <your-project-ref>
```

Schema (tables, RLS, functions, triggers)

```bash
supabase db pull
```

Data (optional)

```bash
supabase db dump --data-only -f supabase/seed.sql
```

Run database

```bash
supabase start && supabase db reset
```

## Authentication

Sign-in is Supabase Auth: email + password, Google and Apple. Credentials live
in `auth.users`; the app only ever touches `public.profiles`.

### One-time dashboard setup

1. **Redirect URLs** — Authentication → URL Configuration. Set **Site URL** to
   something real (a placeholder such as `https://gathermap.app` is enough in
   development) and add `app.gathermap://login-callback` to **Redirect URLs**.
   That is the value of `AUTH_REDIRECT_URL` in
   `lib/controllers/auth_controller.dart`; it must match the Android
   intent-filter in `android/app/src/main/AndroidManifest.xml` and the iOS
   `CFBundleURLTypes` scheme in `ios/Runner/Info.plist`.

   Both entries matter: an unlisted `redirect_to` is **silently replaced by the
   Site URL**, so the confirmation or recovery link opens `http://localhost:3000`
   in a browser instead of the app. An `access_denied` / `otp_expired` page on
   localhost is that fallback, not an app bug.
2. **Email** — keep "Confirm email" on; the app handles both settings. Set the
   minimum password length to at least 6, the value of `kMinPasswordLength` in
   `lib/views/auth/auth_validators.dart`, otherwise the form accepts a password
   the server rejects. The built-in mailer is development-only — see
   [Email delivery](#email-delivery).
3. **Google** — in Google Cloud Console create an OAuth client whose authorised
   redirect URI is `https://<project-ref>.supabase.co/auth/v1/callback`, then
   paste the id and secret into Authentication → Providers.
4. **Apple** — needs a paid Apple Developer account (Service ID + key). App
   Store guideline 4.8 makes it mandatory as soon as Google sign-in is offered.
5. **Deep link scheme** — `app.gathermap` is both the bundle id and the URL
   scheme. Renaming it means editing the two platform files above, the Supabase
   redirect list, and rebuilding.

### Email delivery

The built-in mailer is a development convenience with hard limits:

- it delivers **only to addresses of your Supabase organisation**; any other
  address fails with `email_address_not_authorized`;
- it is capped at **2 emails per hour per project** (Authentication → Rate
  Limits), and at one every 60 seconds to the same address;
- every send **rotates the token**, so only the newest link works. An older
  email reports `otp_expired` — and so does a link a mail scanner prefetched
  before you tapped it.

For anything past a quick test, configure custom SMTP (Authentication → Emails →
SMTP Settings).

To skip delivery entirely while developing, turn **Confirm email** off
(Authentication → Sign In / Providers → Email, then Save). Sign-up then returns a
session and the app goes straight to onboarding. Re-enable it before release,
together with custom SMTP. This only affects sign-up: password-reset and resend
emails still go through the mailer and stay slow until SMTP is configured.

To iterate locally, run the stack and read the mail it captures in Inbucket at
`http://localhost:54324`, with no delivery or rate limits:

```bash
supabase start      # prints the local API URL and anon key for .env
supabase db reset
```

The login screen keeps the address waiting for its link and offers **Renvoyer
l'e-mail**, so an expired or lost link can be replaced from the app. Confirm on
the device that signed up: the PKCE verifier that completes the exchange is
stored there.

### Schema

`supabase/migrations/20261019090000_profiles_and_rls.sql` creates
`public.profiles`, the `on_auth_user_created` trigger that seeds a row from the
sign-up metadata, and the RLS policies for every table. Apply it with:

```bash
supabase db push      # linked project
supabase db reset     # local stack
```

The migration opens with a dev reset: it drops the old `public."user"` table and
clears the content that referenced it.

Until it has been applied, a signed-in account cannot load its profile: PostgREST
answers `Could not find the table 'public.profiles'` (PGRST205) and the gate
shows **Impossible de charger votre profil** with a **Réessayer** button.

## Dart type generation

`lib/models/*.dart` are generated by
[Supadart](https://pub.dev/packages/supadart) from the linked project's schema,
configured in `supadart.yaml`. A table mapping there — for example
`profiles: Profile` — decides the class name and the accessor (`client.profile`).

```bash
# Needs SUPABASE_URL and a *secret* SUPABASE_API_KEY, not the publishable key.
supadart
```

Never edit the generated files by hand. The `tool/gen_types.sh` and `.githooks`
instructions that used to live here pointed at files that are not in this
repository.

## Supabase Configuration

```bash
# Initialize supadart.yaml config file
supadart --init

# Generate classes
supadart --url <supabase_url> --key <supabase_secret_key>

# if SUPABASE_URL and SUPABASE_API_KEY are set in the environment variables
# if SUPABASE_URL and SUPABASE_API_KEY are set in supadart.yaml
supadart

# Generate from schemas other than public (the first keeps plain names)
supadart --schema public,inventory
```
