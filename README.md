## Supabase configuration

Pull your project down:

```bash
npm i -g supabase          # or: brew install supabase/tap/supabase
supabase login
supabase init              # creates supabase/ folder with config.toml
supabase link --project-ref <your-project-ref>
```

Schema (tables, RLS, functions, triggers):

```bash
supabase db pull
```

Data (optional, local only — `supabase/` is gitignored):

```bash
supabase db dump --data-only -f supabase/seed.sql
```

Run database:

```bash
supabase start && supabase db reset
```

## Running the app

Configuration is compile-time. `.env` is gitignored and holds `SUPABASE_URL`
and `SUPABASE_PUBLISHABLE_KEY`:

```bash
flutter pub get
flutter run --dart-define-from-file=.env
```

## Dart type generation

Model types are generated from the linked project's schema by the **Supadart**
CLI (one file per table in `lib/models/`, each with a "auto-generated by
Supadart" header). The config is `supadart.yaml`:

```yaml
SUPABASE_URL: env(SUPABASE_URL)
SUPABASE_API_KEY: env(SUPABASE_API_KEY)   # secret key (sb_secret_...) or service_role
schemas:
    - public
```

Regenerate:

```bash
# SUPABASE_URL and SUPABASE_API_KEY set in the environment or in supadart.yaml
supadart

# or explicitly
supadart --url <supabase_url> --key <supabase_secret_key>

# initialize a config file
supadart --init

# generate from schemas other than public (the first keeps plain names)
supadart --schema public,inventory
```

Each generated table exposes a row class (`Event` with typed fields),
static column tokens (`Event.c_scheduledAt`), payload builders
(`Event.insert(...)`, `Event.update(...)`) and converters
(`Event.converter(...)`, `Event.converterSingle(...)`), plus a
`client.event` extension on `SupabaseClient`.

**Never edit `lib/models/*.dart` by hand** — changes are overwritten on the
next generation. Feature code must not import them either: only the mapper in
`features/<name>/data/` bridges generated rows and domain entities.

> `supabase/` (CLI config + `migrations/*.sql`) is gitignored, so schema and
> migration changes are not committed to this repository.
